# 新增站点无法访问：诊断与修复（2026-10-21）

## 现象

在 `release/config.json` 中新增 21 个资源站后，大部分站点在应用里打不开（列表为空或报"上游请求失败"），但在浏览器里访问同一域名正常。

## 根因

不是配置格式错误，是**网络层 TLS 阻断 + 应用不走系统代理**。

1. 这批域名在当前网络下被 SNI 阻断：TCP 能连上，但 TLS 握手（ClientHello 带 SNI）被 RST。
   实测错误为 `ECONNRESET`，耗时 100~300ms；`curl` 报 `schannel: failed to receive handshake`。
2. 浏览器能打开，是因为浏览器跟随 Windows 系统代理（本机 Clash，`127.0.0.1:7897`）。
3. 应用后端用 Node 的 `node-fetch`，**不读取系统代理，也不读 `HTTPS_PROXY` 环境变量**，只能直连，因此必然失败。

验证：同一条 URL 直连 `ECONNRESET`，经 `-x http://127.0.0.1:7897` 返回 `HTTP 200`。

## 修复

给上游请求层加代理支持，采用 **fallback 模式**：先直连，直连失败才走代理。这样被阻断的站点能打开，可直连的站点速度不受影响。

| 文件 | 改动 |
|---|---|
| `backend/src/config.ts` | 新增 `proxy` / `proxy_mode` 配置字段、`normalizeProxyUrl()`、`getProxySettings()` / `setProxySettings()` |
| `backend/src/services/http.ts` | 新增 `createProxyAgent()`，按目标协议选择 `HttpsProxyAgent` / `HttpProxyAgent` / `SocksProxyAgent`，按代理地址+协议缓存复用 |
| `backend/src/services/upstreamFetch.ts` | 三条请求路径（文本 / 二进制 / 流式分片）全部改为：代理(always) → 直连 → 代理(fallback) → Windows 系统 HTTP 回退；fallback 模式下直连预算 6s |
| `backend/src/routes/movies.ts` | 新增 `GET/POST /api/movies/proxy` |

支持协议：`http://`、`https://`、`socks5://`、`socks5h://`、`socks4://`。

### 配置方式

编辑便携版目录下的 `release/config.json`（exe 同目录），加两个字段：

```json
{
  "cache_time": 7200,
  "api_site": { "...": {} },
  "proxy": "http://127.0.0.1:7897",
  "proxy_mode": "fallback"
}
```

或在应用运行时调接口：

```bash
curl -X POST http://127.0.0.1:<端口>/api/movies/proxy \
  -H "Content-Type: application/json" \
  -d "{\"proxy\":\"http://127.0.0.1:7897\",\"mode\":\"fallback\"}"
```

关闭代理：`{"proxy": null}`。

`proxy_mode` 说明：
- `fallback`（默认）：直连优先，失败才走代理。推荐。
- `always`：全部走代理。适合直连全部不稳定的环境，但会牺牲可直连站点的速度。

## 实测结果（21 个新增站点）

| 状态 | 数量 | 说明 |
|---|---:|---|
| 修复前可用 | 6 / 21 | 只有本身未被阻断的 6 个 `api/json.php` 站点 |
| 修复后可用 | 18 / 21 | 其余靠代理兜底 |

单站耗时（修复后，含代理回退）：`91md` 3.8s、`shayuapi` 4.7s、`dyttzy`（直连）1.5s。

## 剩余 3 个仍不可用：站点本身失效

| 站点 | 代理访问结果 | 结论 |
|---|---|---|
| `lbapiby` | HTTP 502 | 源站不可用 |
| `sexnguon` | TLS 握手失败 | 域名失效 |
| `maozyapi` | HTTP 523 | Cloudflare 源站不可达 |

这三个建议从配置中删除，与代理无关。

## 版本

`1.0.4` → `1.0.5`，产物：`release/Public Domain Cinema-1.0.5-portable.exe` / `-setup.exe`。

## 注意

**不要**让应用读取 `HTTPS_PROXY` / `HTTP_PROXY` 环境变量。本机该变量指向 WorkBuddy 自身代理（`127.0.0.1:63576`），实测无法代理外网流量，且会导致原本正常的站点（如 `dyttzy`）证书校验失败。必须只认配置文件里的显式代理。
